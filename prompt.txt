WEEK 12: OPTIMISTIC CHECK-IN MUTATION
================================================================================

Act as a Senior State Management Engineer implementing optimistic updates.

### PROJECT CONTEXT
- File: `app/src/client/index.ts`
- Goal threshold: 50 XP
- Jotai atom: `$lastCheckIn` stores last check-in response (from Week 10)
- No optimistic leaderboard update — too complex without other users' data

### TASK: Implement useCheckInMutation with optimistic UI feedback

Strategy:
1. **Immediately** update Jotai atom with estimated new values
2. **On success**: Jotai atom gets real server values
3. **On error**: Rollback to previous Jotai state

```typescript
export const useCheckInMutation = (): UseMutationResult<
  CheckInResponse, AxiosError, CheckInParams,
  { previousCheckIn: CheckInResponse | null }
> => {
  const queryClient = useQueryClient();
  const [lastCheckIn, setLastCheckIn] = useAtom($lastCheckIn);

  return useMutation({
    mutationFn: ...,
    onMutate: async (params) => {
      const previousCheckIn = lastCheckIn;
      setLastCheckIn({
        ...previousCheckIn,
        xp_earned: (previousCheckIn?.xp_earned ?? 0) + params.xp_amount,
        goal_met: (previousCheckIn?.xp_earned ?? 0) + params.xp_amount >= 50,
        lessons_completed: (previousCheckIn?.lessons_completed ?? 0) + 1,
        // DON'T optimistically update streak (server authority)
      });
      return { previousCheckIn };
    },
    onSuccess: (data) => setLastCheckIn(data),
    onError: (_, __, context) => {
      if (context?.previousCheckIn !== undefined)
        setLastCheckIn(context.previousCheckIn);
    },
    onSettled: () => {
      queryClient.invalidateQueries({ queryKey: ["gamification"] });
    },
  });
};
```
